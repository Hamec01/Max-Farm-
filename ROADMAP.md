# ROADMAP.md — «Ферма Макса»

## 0. Цель проекта

Создать с нуля детскую 2D-игру про ферму и животных, в которой ребёнок может свободно играть с животными, ухаживать за ними, выращивать растения, развивать ферму и постепенно нанимать работников, которые берут рутину на себя.

Основная платформа — **мобильные телефоны и планшеты**. PC — дополнительная платформа.

Игра должна быть:

- очень простой в управлении;
- визуально живой;
- понятной ребёнку 2–7 лет;
- без перегруженного интерфейса;
- достаточно глубокой, чтобы были уровни, монеты, развитие и долгосрочная цель;
- стабильной при большом количестве животных и работников;
- построенной так, чтобы старые проблемы с позиционированием и перемещением не могли повториться архитектурно.

# 1. Ключевая структура игры

В игре есть две основные семьи игровых сцен.

## 1.1. Animal Habitat — локации животных

Это длинные живые 2D-локации, по которым Макс перемещается горизонтально.

На них находятся:

- животные;
- загоны;
- пруды;
- домики;
- кормушки;
- яблони;
- деревья;
- цветочные точки;
- декоративные бонусные объекты;
- работники;
- бабочки днём;
- падающие звёзды ночью;
- другие небольшие события.

Игрок может:

- гулять;
- гладить животных;
- кормить;
- чистить;
- расчёсывать;
- мыть;
- стричь подходящих животных;
- перемещать животных;
- поднимать и мягко подбрасывать животных;
- собирать продукты;
- ловить бонусы;
- улучшать объекты локации.

## 1.2. Farm Production — ферма / огород

Отдельная рабочая локация с грядками и производством корма.

Макс может:

- выбирать семена;
- сажать;
- поливать;
- ждать роста;
- собирать урожай;
- складывать урожай в инвентарь;
- использовать урожай как корм;
- продавать излишки;
- улучшать грядки и инструменты;
- постепенно передавать работу работникам.

## 1.3. Дополнительные сцены

После основного игрового цикла:

- MAX_HOME — дом Макса;
- рисовалка;
- пазлы;
- мебель и домашние взаимодействия;
- другие спокойные мини-игры.

# 2. Управление и мобильный UX

## 2.1. Основной формат

Игра проектируется в первую очередь для **landscape** на телефонах и планшетах.

При портретной ориентации можно показывать красивую короткую просьбу повернуть устройство.

## 2.2. Перемещение Макса

Основной mobile control:

- тап по свободной земле → Макс идёт к этой точке по X;
- тап по объекту → Макс автоматически подходит к точке взаимодействия;
- keyboard arrows / A-D на PC — дополнительное управление.

Не использовать сложный виртуальный джойстик без необходимости.

## 2.3. Животные

Жесты должны быть естественными:

- tap → погладить / выбрать животное;
- drag → переместить внутри разрешённой территории;
- быстрый drag/flick вверх → мягко подбросить;
- contextual action → кормить;
- contextual action → расчёсывать / мыть / стричь, если действие подходит животному.

Подброс — весёлое действие, а не повреждение. Животное мягко приземляется, подпрыгивает и может показывать сердечки/радость.

## 2.4. Контекстные действия

Постоянно показывать только самое важное.

После выбора животного появляется небольшая панель крупных действий:

- корм;
- ласка;
- уход;
- информация, если нужна.

Не держать все инструменты на экране постоянно.

# 4. Главное архитектурное решение против старых багов

Свободное хаотичное размещение игровых объектов запрещено.

Каждая локация описывается данными и содержит заранее определённые зоны.

Пример:

```ts
interface LocationDefinition {
  id: LocationId;
  worldWidth: number;
  worldHeight: number;
  playerWalkY: number;
  playerSpawnX: number;
  animalZones: AnimalZoneDefinition[];
  buildingSlots: BuildingSlotDefinition[];
  workerAnchors: WorkerAnchorDefinition[];
  interactionAnchors: InteractionAnchorDefinition[];
  flowerSpawns: SpawnPoint[];
  collectiblePaths: CollectiblePath[];
}
```

## Animal Zone

Животное имеет разрешённую область:

```ts
interface AnimalZoneDefinition {
  id: string;
  minX: number;
  maxX: number;
  anchorY: number;
  compatibleSpecies: AnimalSpecies[];
  capacity: number;
}
```

После drag/toss животное всегда ограничивается своей допустимой зоной.

## Building Slot

Пруды, загоны, яблони, домики и другие улучшения покупаются не в произвольное место, а в понятные заранее подготовленные слоты.

Это даёт:

- одинаково красивую композицию на всех устройствах;
- отсутствие наложений;
- предсказуемое сохранение;
- простое улучшение объекта;
- отсутствие сложного pathfinding.

## Worker Anchor

Работники используют точки взаимодействия и горизонтальные маршруты.

Не использовать свободный 2D-pathfinding для работников.

# 5. Животные и уход

У каждого животного есть три мягкие потребности:

- Hunger;
- Affection;
- Cleanliness.

Низкая потребность не убивает животное и не наказывает ребёнка.

Она только:

- показывает понятную иконку;
- уменьшает скорость производства;
- создаёт задачу для Макса или работника.

После ухода животное:

- радуется;
- показывает короткую анимацию;
- может дать маленький XP bonus.

# 8. Перемещение животных между зонами

У каждого вида есть:

Использовать общий Task Board.

Состояния:


# 12. Автоматизация

Начало игры:

- Макс делает почти всё сам.

Средняя стадия:

- работники кормят;
- собирают;
- поливают;
- стригут;
- убирают.

Поздняя стадия:

- ферма может работать почти автоматически;
- игрок занимается животными, перемещением, коллекционированием, развитием и событиями.

Таким образом автоматизация является наградой, а не заменой игры.

---

# 13. День и ночь

Игровой день не привязан к реальным суткам.

Продолжительности находятся в content/config и настраиваются балансом.

Фазы:

```text
DAWN
DAY
SUNSET
NIGHT
```

## DAY

- яркие цвета;
- бабочки;
- цветы;
- обычная работа фермы;
- активные животные.

## NIGHT

- цветовой overlay;
- фонари;
- звёзды;
- падающие звёзды;
- редкие бонусы;
- Masha может автоматически ловить часть звёзд.

Основные действия фермы не должны блокироваться ночью.

---

# 14. Живые события

## Цветы

На специальных точках постепенно растут цветы.

Tap по готовому цветку:

- небольшой XP;
- небольшая монета;
- иногда предмет букета.

## Бабочки

Появляются преимущественно днём.

Двигаются визуально свободно, но не являются полноценными physics entities.

Tap:

- поймать;
- получить небольшой XP;
- получить монеты;
- редкие цвета могут давать больше.

## Падающие звёзды

Появляются ночью.

Нужно успеть tap до исчезновения.

Награда:

- XP;
- монеты;
- редкий star bonus.

События ограничиваются spawn budget, чтобы ребёнок не превращал их в бесконечный farming exploit.

# 15. Прогрессия

Основные показатели:

- Coins;
- XP;
- Player Level.

Не добавлять премиальную валюту на первом этапе.

Уровень открывает:

- животных;
- работников;
- инструменты;
- улучшения;
- новые локации.

Покупка всегда дополнительно требует Coins.

---

# 16. Улучшения локаций

Каждая локация получает собственные upgrade slots.

Пример категорий:

- Capacity — больше животных;
- Comfort — медленнее падают потребности;
- Production — быстрее готовятся продукты;
- Beauty — больше цветов/бабочек/бонусов;
- Automation — работники эффективнее;
- Storage — больше локального запаса.

Улучшение должно менять внешний вид объекта, когда есть соответствующий арт.

---

# 17. Экономика

Правила:

- одна основная валюта — Coins;
- XP не тратится;
- деньги нельзя сделать отрицательными;
- одна покупка не может пройти дважды;
- одна награда не может начислиться дважды;
- цены и награды хранятся в content data;
- UI не изменяет баланс напрямую;
- в начале экономика щедрая и понятная;
- ребёнок не должен ждать час, чтобы снова что-то сделать.

---

# 18. Сохранение

Первый релиз может быть полностью offline-first.

Хранить:

- schemaVersion;
- level;
- XP;
- coins;
- inventory;
- animals;
- animal needs;
- purchased locations;
- workers;
- worker assignments;
- tools;
- upgrades;
- crops;
- game time;
- current location;
- settings.

Не хранить Phaser runtime objects.

Автосохранение:

- после покупки;
- после большой награды;
- после открытия локации;
- после важных изменений;
- по debounce;
- при visibilitychange;
- при pagehide.

Повреждённое сохранение не должно ломать запуск.

- никаких обязательных hover actions;
- никаких маленьких кнопок;
- никаких критических действий по double-click.

---

# 22. Производительность

Цель:

- 60 FPS на нормальном современном телефоне;
- корректная игра при 30 FPS;
- скорость симуляции не зависит от FPS.

Обязательные ограничения:

- никакого interval на каждое животное;
- никакого interval на каждого работника;
- не выполнять тяжёлый worker decision каждый кадр;
- не загружать все локации в GPU одновременно;
- удалять listeners при shutdown сцен;
- использовать object pooling для частых эффектов;
- ограничивать количество частиц, бабочек и звёзд.

# 24. Definition of Done

Любая механика завершена только когда:

1. работает пальцем;
2. работает после resize/orientation lifecycle;
3. не зависит от FPS;
4. сохраняется;
5. загружается;
6. не может начислиться дважды;
7. не создаёт свободное хаотичное положение сущности;
8. имеет тест доменной логики, если логика значимая;
9. не добавляет постоянный UI без необходимости;
10. проверена в production build.

# 25. Главный принцип проекта

**Ферма должна становиться сложнее внутри, но оставаться простой снаружи.**

Ребёнок видит животное и понимает, что с ним можно играть.

Ребёнок видит грядку и понимает, что можно посадить растение.

Ребёнок видит бабочку и хочет её поймать.

Ребёнок видит падающую звезду и нажимает на неё.

А все сложные вещи — экономика, маршрутизация работников, сохранение, timers, upgrades и automation — должны работать незаметно под этим простым интерфейсом.
